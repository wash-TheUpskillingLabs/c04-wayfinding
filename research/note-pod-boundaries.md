# Note for the three pods: where the member-project idea lands

*Context from the Wayfinding pod for Scaffolding and Front Door, Nov 6, 2026. A working hypothesis from the problem owner (see record-problem-owner-hypotheses-nov6.md), not a decision. Shared so each pod can see the seam it owns.*

**The hypothesis.** The Cycle is an incubation sprint and capstone. Sustained projects (ventures and civic tech that came out of past Cycles, and others) are partners, not Labs property: The Labs helps them onboard contributors and uses their real work as learning experiences. The closest documented precedent is the Google Summer of Code / Outreachy shape, whose failure modes are in `research/` (post-program cliff, mentor overwhelm at the gate, stale on-ramp tasks, project interests diverging from learner interests, projects with one keeper).

**The test for which pod owns a question:** *how do I find it and know I'm ready* → Wayfinding. *What happens to me once I'm there* → Scaffolding. *Where does the truth live* → Front Door.

| Wayfinding | Scaffolding | Front Door |
|---|---|---|
| The visible, maintained list of member projects: what each needs, what a newcomer can do first, who to talk to | What a stint inside a member project looks like: pace, check-ins, mentor hours, what counts as done | The data model for projects, roles, contributions and stints in OLOS |
| The match: who is ready for which project, and how they find out | Mentor and maintainer training and support | Whether the list and the record are one source of truth, and how other heads read it |
| The handoffs: Cycle → member project; member project → next Cycle; workshop → member project as a pre-cycle on-ramp | Partnership terms between The Labs and a project (what each owes the other), and a bus-factor rule | |
| A named person on each side of a handoff, as a route element | The learning design that turns a project's real work into a learning experience | |
| The honest exit: finishing a stint and leaving visibly | Everything inside the Cycle, including the capstone format | |
| How a person sees their own route and standing across all of it | | |
| Which notifications move someone across a threshold, from which channel and sender | | |

**Seams worth a line in each repo**
- "Good first tasks" sit on all three: Wayfinding needs them to be current scent; Scaffolding owns what makes one good; Front Door owns where it lives. Nearly half of open-source "good first issues" are never resolved by a newcomer (see `case-oss-newcomer-barriers.md`).
- Retiring a project from the list is a Wayfinding event triggered by a Scaffolding rule.
- The route into running things (participant → teach-back → facilitator → organizer) is a Wayfinding threshold with Scaffolding content.

**On method.** All of this is step 7–8 thinking (futures, transformation) stated early by the problem owner. Frames come from the pod's themes on Nov 7, from evidence. Treat this note as context, not direction.
