# Parked: the Cycle as a distributed clock

*Parked Oct 28 by the steering committee. **A possible future for The Labs, not C04 direction.** Most of it would be the national Board's to decide. It's here so the pod can test its thresholds against it: if The Labs worked this way, which thresholds would matter most, and what would people need to see?*

## The idea

**The Cycle isn't the destination for most people.** Supported, maintained projects can be the longer-term experience: more mature problems and communities than the projects a Cycle incubates from zero.

**The Cycle stays what it is: a sprint, an incubator.** It's always where new things get made. What changes is what it's applied to:

- **New problems.** A problem situation nobody is working on yet, and a project started from zero, as in C04.
- **Enduring projects and spinouts.** A project that already has a community brings its *current problem situation* into the Cycle. Not a feature. Nobody knows the feature ahead of time. The Cycle does the same work it always does: archaeology, paradox, themes, frames, then build. What gets built comes out of the research. Newcomers learn the project by doing that work alongside its maintainers.

**One clock, run nationally, facilitated locally.** As sectors develop mature communities and projects, the Cycle could run on a shared national calendar, with each region facilitating locally. Enduring projects use it to onboard new contributors and to innovate.

**The rhythm.** Between Cycles, maintained projects run steadily: fixes, upkeep, community. During a Cycle, everyone sprints on something new.

## Why it might matter for wayfinding

- **A predictable clock is a sign.** If everyone knows when the next on-ramp opens, "what's next" is easier to answer, before, during and after a Cycle. People can prepare toward a date.
- **Two kinds of time to orient by:** the steady state of a project you belong to, and the next sprint you can join.
- **New thresholds:** from a Cycle into a maintained project, from a maintained project into the next Cycle, and maybe straight into a maintained project without a Cycle.

## Cases worth logging

- **Google Summer of Code and Outreachy.** A central program runs the calendar and the matching; established open-source projects mentor newcomers inside a fixed window. Many contributors stay on afterward.
- **Release trains** (Ubuntu every six months, Python yearly). A shared date everyone plans around.
- **Campaigns,** in The Labs' own strategy: many regional Cycles starting the same day, with one method.
